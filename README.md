# reg58.me

My personal site: a portfolio with a Gulf-livery racing theme, plus a private smart home dashboard that controls my house through [Home Assistant](https://www.home-assistant.io/).

**Live:** [reg58.me](https://reg58.me)

## Features

- **Portfolio**: project cards are pulled live from my public GitHub repos, shown in a swipeable carousel on the home page and a filterable grid on `/projects`.
- **Smart home dashboard** (`/dashboard`, owner only): lights with dimming, switches, fans, thermostats, locks, blinds and sensors, grouped by room and refreshed every 10 seconds.
- **Now playing**: a panel beside the intro shows what I'm listening to on Spotify (or the last song played), checked every few seconds through a small server endpoint that never exposes the Spotify keys.
- **Racing-inspired design**: Gulf blue and orange palette, a livery stripe where a top-down 2026-style F1 car drives across as you scroll (shown complete when reduced motion is requested), and a custom overlay scrollbar so the stripes run edge to edge.

## Tech stack

- [SvelteKit 3](https://svelte.dev/docs/kit) + Svelte 5 (runes) + TypeScript
- Hosted on [Vercel](https://vercel.com) (`@sveltejs/adapter-vercel`)
- Home Assistant REST and WebSocket APIs for device control
- GitHub REST API for the project list
- No database: sessions are signed cookies and configuration lives in environment variables

## How it works

```
Browser ──► SvelteKit on Vercel ──┬──► GitHub API          (public repos → project cards)
                                  └──► Home Assistant API  (dashboard, server-side only)
```

- **Server-only secrets**: the Home Assistant token and GitHub token are only ever read in server code (`src/lib/server/`, `$app/env/private`). SvelteKit refuses to bundle these into browser code, so they can't leak to visitors.
- **Device providers**: `src/lib/server/devices/` defines a small `DeviceProvider` interface with two implementations: Home Assistant, and an in-memory demo provider used when Home Assistant isn't configured.
- **Rooms and hidden entities** come from Home Assistant's WebSocket registries, which work with a non-admin token (the REST template API needs admin).
- **GitHub projects** are cached in memory for 10 minutes. Forks are skipped; add the `portfolio` topic to repos to pick exactly which ones appear.

## Security

- `src/hooks.server.ts` guards every request: anything under `/dashboard` or `/api/devices` without a valid session redirects to `/login` (pages) or returns `401` (API).
- The password is stored only as an **scrypt hash**. Sessions are HMAC-signed cookies (`HttpOnly`, `Secure`, `SameSite=Strict`).
- **Two-factor login**: after the password, a 6-digit code from an authenticator app (TOTP, RFC 6238, implemented with Node's built-in crypto). Each code works once. Ticking "Remember this device for 30 days" sets a signed cookie that skips the code on that browser only.
- Signed cookies carry their purpose (session, pending login, trusted device) inside the signature, so one kind can't be swapped in for another.
- Failed passwords and codes are rate limited per IP, and post-login redirects only allow local paths.
- Home Assistant is reached through a tunnel with no open router ports, using a dedicated non-admin user.
- Security headers on every response (`X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`).

## Run it yourself

Requires Node.js 22+.

```bash
npm install
npm run set-password   # creates .env with a password hash and session secret
npm run dev            # http://localhost:5173
```

Without Home Assistant settings, the dashboard uses demo devices, so you can try everything locally.

### Environment variables

| Variable | Required | Purpose |
| --- | --- | --- |
| `AUTH_PASSWORD_HASH` | For login | scrypt hash of the dashboard password (`npm run set-password`) |
| `SESSION_SECRET` | For login | Signs session cookies (generated by `npm run set-password`) |
| `TOTP_SECRET` | No | Turns on two-factor codes (generated by `npm run setup-2fa`) |
| `HA_URL` | No | Home Assistant URL; leave empty for demo devices |
| `HA_TOKEN` | No | Home Assistant long-lived access token (use a non-admin user) |
| `GITHUB_TOKEN` | No | Raises the GitHub API limit from 60 to 5,000 requests per hour |
| `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`, `SPOTIFY_REFRESH_TOKEN` | No | Turn on the "now playing" panel (set up with `npm run setup-spotify`) |

See `.env.example`. Never commit `.env`; it's in `.gitignore`.

### Make it yours

| What | Where |
| --- | --- |
| Name, tagline, about, links, GitHub username | `src/lib/site.ts` |
| Extra project cards (for example, private repos) | `src/lib/projects.ts` |
| Colours | `src/app.css` (three base colours at the top) |

### Deploy

1. Import the repo into Vercel (it detects SvelteKit automatically).
2. Add the environment variables above in **Settings → Environment Variables**.
3. Deploy. Every push to `main` redeploys.
